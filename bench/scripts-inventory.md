## Containerized N-Times A/B Harness Requirements (Critical Guardrails)

Before running any starter-set script N times under `bashy` vs GNU `bash` 5.3 inside containers on the gate host, the harness MUST enforce four invariants so measurements are apples-to-apples:

1. **Prevent child subshell escape (`PATH` shimming)**: Several real suites invoke child scripts via `bash script.sh`, `sh script.sh`, or `#!/usr/bin/env bash` shebangs (e.g., `builds/check.sh`, `toolchain-gate-test.sh`, `test-campaign-distribute.sh`, `test-dks-select-node.sh`, `test-dks-profile.sh`, `test-meet-spa-fresh.sh`, `test-release-qa-lane.sh`). In a container where `/usr/bin/bash` is GNU bash, running `bashy script.sh` without shimming `PATH` causes child scripts to execute under GNU bash, silently diluting the measurement. The `bashy` run MUST prepend a shim directory on `PATH` mapping `bash` and `sh` to `bashy` (and verify `/bin/sh` / `/bin/bash` behavior where absolute paths appear, e.g. `test-release-provenance-cleanup.sh`).
2. **Controlled coreutils & external tools**: Record exact versions of GNU bash, GNU coreutils, `jq`, and `git` in the container image. For scripts using `jq` (`S11`) or `git` (`S05`, `S15`), both runs must invoke the identical external `jq`/`git` binary (or explicitly document whether `bashy`'s in-process `git` vs external `git` is part of the comparison). Note that three scripts (`test-campaign-distribute.sh:22`, `test-dks-profile.sh:17`, `test-dks-select-node.sh:35`) call `/bin/rm -rf "$tmp"` in `EXIT` traps, which is fine inside Linux containers and happens once per run.
3. **Correctness guard before timing**: Capture exit code, normalized stdout/stderr (stripping only temp-dir paths if printed), and output-tree digests (`sha256sum` over rendered outputs for `S01`/`S07`). Any behavioral or output divergence between `bashy` and GNU `bash` 5.3 is a finding to root-cause, never a speed data point.
4. **Clean per-iteration isolation**: Run every iteration inside a fresh temp workspace with `LC_ALL=C`, `TZ=UTC`, `BASHY_HINTS=off`, `BASHY_TELEMETRY_QUIET=1`, and `--network=none` at the container boundary to guarantee airgapped repeatability.

### Offline & Repeatability Legend

- `yes` — Runs offline and repeatably as-is inside a standard Linux container (repo checkout + standard coreutils/`jq`/`git`).
- `yes-with-fixture` — Runs offline and repeatably with no script edits, requiring only a pinned input argument, fixture directory, or stubbed env/PATH binary.

- `no-unsuitable` — Cannot run under GNU bash (Bash#-only syntax or declarative `contract.bsh`), OS-locked (macOS/Windows-only), or dominated by live containers/compilers/network/media/LLM runtimes.
